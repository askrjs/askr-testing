# Testing 0.5 API decisions

Baseline: `@askrjs/testing@0.4.1`, 18 root declaration names. Candidate: 11 names
(three values and eight types). All 18 names and both export-map keys are reviewed below.
This is a breaking candidate, with no compatibility shim and no publication yet.

## Export keys

| Key              | Decision | Consumer contract                                                                      |
| ---------------- | -------- | -------------------------------------------------------------------------------------- |
| `.`              | KEEP     | One HTTP injection entrypoint; distinct from component/runtime `@askrjs/askr/testing`. |
| `./package.json` | KEEP     | Package/version and engine metadata for installed tooling.                             |

No implementation subpath is public. The installed artifact rejects nine representative private
paths, including source files, implementation owners, and `dist/index.js`.

## Every baseline name

| Name                  | Decision | Concrete reason or migration                                                                                                                    |
| --------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `createTestClient`    | KEEP     | README repeated method calls share base URL, headers and optional session jar.                                                                  |
| `inject`              | KEEP     | README one-request route tests and caller-owned native Requests need no client state.                                                           |
| `createTestCookieJar` | KEEP     | README seeds a jar, reads session state, clears it and shares it across clients.                                                                |
| `createTestRequest`   | REMOVE   | Duplicates path/options construction owned by injection. Use `inject(target, path, options)`, or native `new Request` when retaining a Request. |
| `TestClient`          | KEEP     | Applications can type an injected reusable client dependency and derive per-method options.                                                     |
| `TestClientOptions`   | KEEP     | Shared application-test fixtures configure base URL, headers and cookie policy explicitly.                                                      |
| `InjectOptions`       | KEEP     | Reusable request cases encode the method/body-mode union and per-request overrides.                                                             |
| `Injectable`          | KEEP     | A test fixture can accept either an application fetch object or a handler without duplicate types.                                              |
| `TestCookieJar`       | KEEP     | External/shared async cookie stores implement an explicit interface; cancellation probes use this seam.                                         |
| `TestCookie`          | KEEP     | Cookie inspection and custom stores need the persisted readback shape, including security fields.                                               |
| `Query`               | KEEP     | Reusable URL query fixtures accept records, iterables and URLSearchParams with repeated scalar values.                                          |
| `Form`                | KEEP     | Reusable URL-encoded body fixtures express form encoding separately from the query location.                                                    |
| `BodyRequestOptions`  | REMOVE   | Derive `Extract<InjectOptions, { method: string }>` or `Parameters<TestClient["post"]>[1]`; no separate exported method branch.                 |
| `GetHeadOptions`      | REMOVE   | Derive `Parameters<TestClient["get"]>[1]` or `Parameters<TestClient["head"]>[1]`.                                                               |
| `RequestHandler`      | REMOVE   | Use `Injectable` for a target, or an explicit `(request: Request) => Response \| Promise<Response>` function type.                              |
| `RequestTarget`       | REMOVE   | Use `Injectable`, or `{ fetch(request: Request): Response \| Promise<Response> }` when an object-only dependency is required.                   |
| `QueryValue`          | REMOVE   | Leaf encoding type is private. Use `Query` for the input, or `string \| number \| boolean` for an individual scalar.                            |
| `FormValue`           | REMOVE   | Leaf encoding type is private. Use `Form` for the input, or `string \| number \| boolean` for an individual scalar.                             |

`Query` and `Form` have the same accepted scalar shapes but represent separate documented request
fields. `Injectable` replaces the two duplicate target aliases. Internal types needed to describe the
retained signatures remain declared privately; declaration reachability is not a new root export.

## Consumer search and migration

The compiler baseline inventory and a text search covered sibling packages, examples, CLI templates,
website, Destroyer, package docs and tests. The seven removed names have no external package source
consumer in that inventory. Own unit tests now import the private request builder from its owner;
public fixtures and packed consumers use native Requests or injection options. README no longer
recommends the separate constructor. All removed names have negative strict TS6 and TS7 assertions.

The website's 0.4 generated snapshot and authored HTTP guide still need the coordinated 0.5 rebuild
and migration. API issue #45 stays open until that site work and the complete normal-install package
graph pass. This package's accepted checks alone do not close that issue.

## Observable changes

- `maxRedirects` defaults to 10 and accepts only non-negative safe integers, including zero. Invalid
  client defaults, request overrides and direct-injection options fail before invoking the target.
- Stream bodies supplied through request options now set Node's required `duplex: "half"` automatically.
- Abort remains observable while waiting for a custom jar. Responses arriving after abort or held during
  an aborted cookie capture are discarded. An already-started store write cannot be rolled back.
- Custom cookie-store read/write failures reject with their original error. Only the built-in jar's
  cookie-policy rejections are ignored during response capture. A custom store that intentionally
  ignores an invalid cookie should resolve normally from `setCookie`.

The injection boundary and cancellation limitations are documented in README. This package does not
add browser rendering helpers, a socket emulator, or implicit global test state.
